# LOOP PRODUCT GUARDRAIL DIRECTIVE

> This directive overrides all future feature work.

## Before building any feature, answer:

1. Does this increase **trust**?
2. Does this increase **human connection**?
3. Does this increase **belonging**?
4. Does this increase **retention**?
5. Does this fit the **Loop vision**?

If the answer is **NO** — do not build it.

---

## Loop is NOT

- Discord
- Telegram
- WhatsApp
- Clubhouse
- X Spaces

Do not copy competitors.

---

## Loop IS

- Trust-first communities
- Regional belonging
- Identity-driven participation
- Human connection
- African-first social infrastructure

---

## Founding Question

Every screen must answer:

- **Who is here?**
- **Why should I care?**
- **What should I do next?**
- **Why should I return tomorrow?**

---

## Community First

A user should never feel alone.

Empty states must:
- Recommend rooms
- Recommend people
- Recommend communities

**Never show dead ends.**

---

## Trust First

Never fake:
- Online status
- Verification
- Notifications
- Community activity
- User counts

**Honesty is mandatory.**

---

## Regional Belonging

Loop should feel Lagos, Abuja, Port Harcourt, Accra, Nairobi, Johannesburg
before it feels Silicon Valley.

---

## Feature Freeze Rule

No major new feature may be built until:

- [ ] Authentication
- [ ] Profiles
- [ ] Rooms
- [ ] Audio
- [ ] Notifications
- [ ] Search
- [ ] Communities
- [ ] Mobile responsiveness

all pass certification.

---

## Founder Test

Before shipping, ask:

- Would a **first-time user trust this**?
- Would they **understand it**?
- Would they **return tomorrow**?

If not — do not ship.

---

## Success

Loop should feel like **a place people belong**, not a place people visit.

Protect this principle above all future development.
